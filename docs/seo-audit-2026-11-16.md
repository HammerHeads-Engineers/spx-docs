# Post-cutover documentation search audit

The production crawl on 16 November 2026 covered all 136 URLs discovered through
the published GitBook sitemap. A separate published-navigation check verified
all 148 legacy HTML and Markdown page redirects against the migration manifest.
Both checks used the current public documentation, not guessed source paths.

## Findings and changes

- All sitemap pages returned HTTP 200 with a self-referencing canonical, one H1
  and no current indexing prohibition. No broken fragment targets were found.
- The Integrations index linked BACnet through an obsolete absolute URL which
  returned 404. It now uses the adjacent `bacnet.md` source, allowing GitBook to
  resolve the current public route.
- 85 published Markdown pages had no description. Each now has a concise English
  description based on its existing content. Navigation, URLs, release pins and
  executable examples are unchanged.
- `check_navigation.py` now requires a nonempty text description on every
  published Markdown source, deriving the source list from `SUMMARY.md`. Hidden
  maintainer pages and GitBook-generated OpenAPI pages are outside that check.
- The two generated OpenAPI pages also lacked descriptions in the live HTML.
  They are generated by the existing GitBook API integration, not Markdown
  sources; verify their metadata separately in GitBook. Do not create duplicate
  reference pages or hand-edit the generated OpenAPI export to patch SEO.
- Short reference index pages are navigation hubs; their word count alone is not
  a reason to pad them with repeated material.

## Verification and publication

Local checks: Markdown links/anchors, published navigation, release rendering,
tutorial rendering and 24 unit/tutorial tests pass. CI also verifies the generated
catalog against its immutable source commit. After Git Sync publishes the merge,
repeat the public crawl and published-page checks to verify actual HTML metadata.
The WWW Search Console workflow can submit both sitemaps and inspect all current
URLs under the existing Domain property with Full service-account access.

Submission and index inspection do not force Google to crawl or index every URL.
Preserve old redirects and compare stored crawl dates with the publication date
before treating a historical noindex result as a current serving defect.
